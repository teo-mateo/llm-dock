SUMMARY TEXT
  • bash: $ first line of the command with a leading cd X && stripped; · exit N in red when non-zero; · timed out.
  • edit: file name, +adds −removes from the result patch; · failed on error.
  • read: file name + line range (L40–79), or · image.
  • write: file name + line count.
  • process: action + name + first command line.
  • chatterbox_*: target + first line; look kind + count; join/leave channel.
  • anything else: today's argsSummary.
  • Any parse failure falls back to argsSummary — a summary never throws.

READ
  • Range chip: lines 40–79, from line 40, or none for a whole file.
  • Numbered lines start at offset (1 when absent); the gutter is not selectable, so copying grabs code only.
  • Image results: a thumbnail (max 320px, click opens full size in a new tab) plus mime and size.

PROCESS
  • Status chip: running = amber, exited/success = green, failed/killed or non-zero exit = red, anything else neutral. Then name, pid, and a small key/value grid (command, cwd, id, exit code).

CHATTERBOX
  • send: target (→ name or → channel), private chip, outcome chip (confirmed green, anything else red with the message), the text in a bubble.
  • look: one line per message — time (HH:MM), sender (bots in info blue), text. Messages addressed to the session get an accent tint; important ones amber text.
  • join / leave: a single meta line.
GENERIC
  • Args as a key/value grid when they parse as an object (raw text otherwise), then the result text in a code block. This is also what every viewer falls back to when its payload doesn't parse.
